API Restaurant

Contexto

Projeto desenvolvido em um desafio da Rocketseat, com foco exclusivo em back-end. O objetivo foi criar uma API para gerenciamento de um restaurante, permitindo operações como cadastro de pratos, categorias e pedidos.

Desafio

Construir uma API RESTful completa, sem interface visual, mas com rotas bem definidas para manipulação de dados. O foco foi aprender sobre:

  • Estruturação de rotas e middlewares.
  • Conexão com banco de dados relacional.
  • Criação de migrations e seeds com Knex.
  • Boas práticas com TypeScript.

Solução

A API foi estruturada utilizando Node.js com TypeScript para garantir tipagem e organização do código. O framework Express foi usado para gerenciar as rotas e middlewares, enquanto o Knex.js serviu como query builder para facilitar a comunicação com o banco de dados SQLite3.

  • Rotas RESTful para pratos, categorias e pedidos.
  • Migrations e seeds com Knex para criar e popular o banco de dados de forma automatizada.
  • Validação de dados e tratamento de erros nas requisições.

Resultado

A API permite:

  • Criar, listar, atualizar e excluir pratos.
  • Organizar pratos por categorias.
  • Gerenciar pedidos de forma estruturada.

Como executar localmente

  1. Clone o repositório do projeto: git clone https://github.com/soarezzgzs/api-restaurant.git
  2. Entre na pasta do projeto: cd api-restaurant
  3. Instale as dependências: npm install
  4. Configure o banco de dados: npm run knex:migrate Opcional: execute os seeds para popular dados iniciais: npm run knex:seed
  5. Inicie a aplicação local: npm run dev
  6. Teste a API: O repositório já inclui um arquivo do Insomnia com todas as rotas configuras, basta importar o arquivo no Insomnia para ter acesso às requisições prontas (GET, POST, PUT, DELETE). Assim você pode testar facilmente os endpoints sem precisar configurar manualmente.

Aprendizados

  • Estruturação de projetos em Node.js.
  • Criação de rotas e manipulação de dados no backend.
  • Integração entre frontend e backend em ambiente local.
